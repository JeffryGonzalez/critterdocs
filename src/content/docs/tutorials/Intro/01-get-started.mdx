In this first tutorial, we want to show you how easy it is to get started with the Critter Stack in building HTTP APIs.

We feel it is important to start with a simple example that demonstrates the core concepts of the Critter Stack. The "key" to success with this JasperFx stack is to understand the *idioms* and *patterns* that are used to build applications with it. 
These patterns are based on well-established software design principles, like event sourcing and messaging. These patterns are so well known, in fact, that the Critter Stack takes care of a lot of the boilerplate and implementation details for you. 

While the various pieces of the Critter Stack can be used as libraries to supplement and strengthen your existing applications, here we want to emphasize using the Critter Stack as a complete *framework* for building your applications.

Unlike a lot of tools and frameworks that try to make things "easy" for beginners, but overly complicated for "real world" work, you will find that the Critter Stack has tons of affordances for even the most advanced applications. We like to say that it "makes the easy stuff easy, and the hard stuff possible". 

## The Happy Path

Let's say you have a user-facing application that allows the user to create a list of training courses, delete them, assign instructors to them, all that stuff. It's *basically* a "todo list", but I teach software development for a living, so it is going to be a course list.

The frontend is a Single Page Application (SPA) that is served up by the backend, which is a .NET API. We are implementing a simple "Backend for Frontend"[^1] pattern.

The backend will handle the business logic, and the frontend will handle the user interface. 

Our "business logic" will be an HTTP API that uses the Critter Stack's Wolverine Endpoints to communicate with the frontend.

We will implement the following endpoints:
- `GET /api/courses` - Get a list of courses
- `POST /api/courses` - Create a new course
- `DELETE /api/courses/{id}` - Delete a course
- `POST /api/courses/{id}/instructor` - Assign an instructor to a course

We will also implement a "bonus" endpoint (`GET /api/course-archive`) to show a historical list of all the courses that have been created, deleted, and instructors assigned to them as a way to explore more advanced **Projections** in the Critter Stack.

In the next section, we will get you setup with a starter project if you'd like to "play along" with the code examples.



[^1]: [Backend for Frontend](https://samnewman.io/patterns/architectural/bff/) is a pattern that allows you to create a separate backend for each frontend application, allowing for more flexibility and scalability in your architecture.
